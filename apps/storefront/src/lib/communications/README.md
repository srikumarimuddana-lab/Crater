# Communications and CRM

`getOperationsStore` selects the private Postgres store when `COMMERCE_DB=postgres`, or an adapter attached to the shared commerce memory repository for development. Migration 0008 persists customer/order links, append-only consent/notes/audit events, conversations, templates, campaigns, callback receipts and the outbox. Postgres mutations lock a singleton row: uniqueness and consent checks are atomic across workers, and provider calls happen outside transactions. This is a single-merchant, modest-volume implementation; split the state document into indexed aggregate rows before large campaigns or long retention histories.

## Integration contract

- `recordCustomerOrder({orderId,email,totalMinor,refundedMinor?,currency,mode,occurredAt,name?,phone?})` links by normalized email. One order/mode has one customer link; replay does not regress refunded amounts.
- `enqueueNotification({eventKey,channel,recipient,templateKey,variables,mode,customerId?,orderId?,marketing?})` snapshots template and destination. Persistent key is `mode:eventKey:channel`.
- Order bridge keys must be `order:ID:paid` and `order:ID:shipped` to match `reconcileOrderCommunications()`. Refund keys should include the provider refund ID. Catch-up scans authoritative committed orders, rejects unknown Stripe mode prefixes, and recovers gaps between payment commit and outbox write. Recovery reads succeeded finance refunds to update CRM refund totals and queue provider-ID-keyed refund notices. It scans all durable shipment rows, and uses shipment keys instead of a duplicate final-order fulfilment notification when partial shipments exist. Every notification carries the customer link so withdrawals and anonymization apply to shipping and refunds too.
- Job states distinguish accepted from delivered. Expired processing leases, connection failures and ambiguous 5xx results become Unknown. Only definitive rejection and rate-limit failures may be retried automatically; staff reconcile Unknown using a verified provider ID. No exactly-once SMS claim is made.
- Signed delivery receipts are saved even before a job's provider ID is committed, then reapplied on acceptance. Unrecognized event types are acknowledged without mutation. Signature or persistence failure is not acknowledged as success.

## Configuration

All providers remain paused unless `COMMUNICATIONS_SEND_ENABLED=true`. Live jobs additionally require `COMMUNICATIONS_ALLOW_LIVE=true`. Test jobs can send only to exact comma-separated `COMMUNICATIONS_TEST_RECIPIENTS`. `COMMUNICATIONS_MODE=test|live` selects the mode for support, staff and newsletter jobs. Keep `test` during setup.

Resend requires `RESEND_API_KEY`, `RESEND_FROM`, `RESEND_REPLY_TO`, and `RESEND_WEBHOOK_SECRET`. Configure `/api/webhooks/resend` for delivery, bounce, complaint and receiving events. Receiving retrieves the plain-text body from the fixed Resend receiving endpoint using the signed email ID.

Twilio requires `TWILIO_ACCOUNT_SID`, `TWILIO_API_KEY_SID`, `TWILIO_API_KEY_SECRET`, `TWILIO_AUTH_TOKEN`, `TWILIO_MESSAGING_SERVICE_SID`, `TWILIO_STATUS_CALLBACK_URL`, and `TWILIO_INBOUND_WEBHOOK_URL`. Both public URLs target `/api/webhooks/twilio`; signature validation uses each exact configured HTTPS URL and all form parameters. SMS sends require purpose-specific consent. Inbound STOP suppresses SMS; signed START/UNSTOP removes only the STOP suppression and does not grant marketing consent.

Newsletter POST `/api/consent` accepts `{email,channel:"email",consent:true,source:"newsletter"}`. It queues an expiring, one-use mailbox confirmation; only the confirmation POST records marketing consent. It needs `COMMUNICATIONS_UNSUBSCRIBE_SECRET` and configured, enabled Resend delivery (including the recipient allowlist in test mode); otherwise it returns an honest unavailable response and queues nothing. Marketing sends also require `COMMUNICATIONS_POSTAL_ADDRESS` and `SITE_URL` (fallback `NEXT_PUBLIC_SITE_URL`), and append signed unsubscribe links. GET confirmation/unsubscribe pages never mutate preferences, to tolerate email scanners.

Contact POST `/api/contact` accepts `{email,subject,message,requestId?,website?}`. Both public endpoints accept native form-encoded POSTs as well as JSON, enforce byte limits and the configured same origin, and rate-limit email requests. Native forms receive an accessible HTML receipt or error page with no submitted contact values in the URL; enhanced clients retain JSON responses. Newsletter checkbox consent is validated on the server. The website field is a honeypot. Add a deployment/WAF IP limit before exposing high-traffic public endpoints; forwarded IP headers are not trusted here.

Schedule authenticated `POST /api/communications/process` with `Authorization: Bearer COMMUNICATIONS_WORKER_SECRET`, or use the Owner/Admin manual worker in Inbox. It reconciles order jobs before processing a bounded batch. No timers or detached promises are used.

## Verification and privacy

Unit tests cover role gates, transactional rollback, deduplication, concurrent claims, lease expiry, consent recheck, STOP, campaign explicit send, callback ordering, signature vectors, stale templates, test-send guard and unknown outcomes. Postgres tests run with a throwaway `TEST_DATABASE_URL` and otherwise visibly skip. Real provider delivery and externally hosted callback verification require staging credentials and explicit sandbox verification; implementation tests make no real sends.

Staff invitation/reset templates are excluded from inbox delivery lists and customer exports. Their bearer-link message bodies remain private to worker storage. Customer export requires CRM access and is audited; anonymization requires Owner/Admin and retains original commerce financial snapshots. Customer merges require Owner/Admin preview and explicit confirmation. They move order links and tags while retaining a redirecting source tombstone, original source consent and message history, and an audit event. No consent transfers; pending source messages are suppressed. Consent is bound to the exact email address or phone at capture time. Changing a phone requires new consent. Automatic SMS order/shipment messages are queued only when explicit transactional consent predates the business event, preventing historical-message blasts after a new opt-in.
