# Commerce implementation verification — 2026-10-14

This is implementation evidence, not a production launch certification. No real charges, refunds, campaigns or messages were sent. No hosted store or production database was changed. Configuration and operating limits are documented in [the platform guide](../../commerce-platform.md).

## Automated evidence

- Full Vitest run: **510 passed, 156 skipped**, across 45 files. The skips are database-dependent tests when no native `TEST_DATABASE_URL` is configured. An additional seven checkout-quote route cases cover malformed JSON, cross-origin requests, bounds and cookie-owned pricing.
- TypeScript check and production Next.js build pass. ESLint has no errors; remaining warnings concern intentionally direct image elements serving pre-encoded reference assets and authenticated media derivatives.
- Production browser commerce regression: **79 passed, 3 expected viewport skips** at 390 and 1440px. Covers product/variant choice, add/update/remove cart, taxes, failed network actions, drawer focus, menu navigation, no-JavaScript forms, empty/error states and axe checks on product/cart/drawer.
- Password-only auth and private media/CMS production browser workflows: **16 passed** at 390 and 1440px, including private upload, draft, authenticated preview, publication and revision restoration.
- Admin operational browser flows: **14 passed** at 1440px, including role-specific views and draft product → variant → duplicate rejection → supplier → purchase order → receipt → stock.
- Expanded admin accessibility/settings: 72 cases passed across mobile and desktop (70 in the initial run plus two login target-size cases after a fix and targeted rerun). Every new module was included in the axe scan; all core admin overflow checks passed after toolbar wrapping.
- Reference home checks across 390/768/1440px: **41 passed, 4 expected viewport skips** across initial and targeted reruns. Covers catalog filtering/search, routine keyboard controls, navigation, consent, reduced motion, no horizontal overflow, skip link, axe, image failures and actual native add-to-cart without JavaScript. This number combines completed runs; it is not one clean all-project run.
- All 12 SQL migrations executed against a temporary PGlite engine. Focused tests executed real PostgreSQL repository SQL using a temporary serialized Pool adapter: auth 29; account management 14; admin services 28; commerce schema 8; admin migrations 8; CMS 2; inventory 3; finance 3; communications 2; analytics 1. Checkout/pricing/tax/webhook-focused memory+SQL validation also passed (161 assertions). Adapter and engine were verification-only dependencies, not added to the application.

The PGlite adapter checks SQL and transactional semantics, including JSONB serialization, but serializes connections. It does **not** establish native multi-process lock/contended transaction correctness. The native PostgreSQL CLI bootstrap subprocess and full persistent-server/provider integration suite remain staging requirements.

## Review findings resolved

## Required staging checks before launch

Use a persistent throwaway PostgreSQL database, configured provider sandbox credentials and a scheduled worker. Run the native integration suite and complete E03/E05/E12 end to end, verify each callback URL/signature, exercise refund reconciliation and a backup restore, and publish real products/policies. Keep payment/message live flags off until those checks and owner operational setup are complete. See `.env.example` for required configuration names; credentials never belong in this repository.
